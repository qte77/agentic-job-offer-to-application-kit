# Board/aggregator catalog — claude-job-hunt (reference only)

This catalog documents every job-board/ATS/aggregator adapter found in
[`dominiquevienne/claude-job-hunt`](https://github.com/dominiquevienne/claude-job-hunt) as of
2026-10-11, with a feasibility assessment against this repo's own ingest model. **Nothing here is
adopted by this change** — it is a reference for future sourcing work, requested so that boards
already investigated (feasible or not) are not re-researched from scratch.

claude-job-hunt's own registry lives in two places: `shared/boards/*.md` (544 cards, one per
board/ATS family — the authoritative list used below) and `skills/job-scan/scripts/*.py` (313
Python files, of which roughly 250 are per-board scrapers and the rest are shared helpers for a
generic JSON-LD/sitemap/microdata engine that covers boards with no dedicated script). The "Bespoke
adapter" column in the ATS/HR-platform table reflects whether claude-job-hunt built a dedicated
script for that platform, not whether it is feasible for *this* repo.

## Method

- **Already-tiered rows** (no `[verified]` tag) carry this repo's own existing classification —
  [ADR-0002](decisions/0002-source-tos-tiers.md) or `docs/research.md` — for a platform/aggregator
  this repo has already assessed: Greenhouse, Lever, Ashby, Personio, swissdevjobs (OK/shipped);
  Recruitee, Workable (CAUTION — a public API/feed exists but the ToS/robots conflict is
  unresolved, so ADR-0002 keeps them out of `config/default-seed.json`); LinkedIn, Indeed,
  StepStone, jobs.ch (BLOCKED — structurally barred); Adzuna, Jooble (keyed/commercial, outside the
  no-auth/no-key model). **This catalog only has three tiers, with no separate "under review"
  tier**, so CAUTION and BLOCKED both land on **Infeasible** here — that column means "not
  currently shippable," not "structurally impossible": Recruitee/Workable's underlying API is
  real and working, but this repo won't ingest it until the ToS question is resolved. These rows
  are not re-derived from claude-job-hunt's card.
- **Rows marked `[verified 2026-10-11]`** were read in full this session (the card's complete text,
  not just its metadata) and classified against this repo's constraints directly. 17 rows carry
  this tag (5 ATS platforms already shipped by this repo + 12 individually read this session).
- **All other rows (the large majority) are classified mechanically**, and this is the most
  important caveat in this document: each claude-job-hunt card's metadata
  (`<!-- hosts/script/countries -->`) plus a keyword scan of its body (robots.txt/disallow
  mentions, browser-automation/login mentions, 403/Cloudflare mentions, paid-tier mentions, CAPTCHA
  mentions) feeds a conservative rule set — it is not a human reading each card. **On the 12 cards
  read in full this session beyond the already-tiered set, the heuristic's initial call was wrong
  on 4 of them** (`bebee` and `computrabajo`: heuristic said Infeasible, the card showed a feasible
  sitemap/HTML route instead; `labonnealternance`: heuristic said Feasible now, the card showed a
  registered-key requirement instead; and the heuristic's "Feasible now" branch itself had to be
  removed after a first pass put 45 of 50 rows in that tier, nearly all of them wrong on inspection).
  That is roughly a 1-in-3 error rate on a small, non-random sample biased toward the most
  "interesting"-looking cards — **treat every unverified tier below as a triage hypothesis to check
  before acting on it, not a finding.** Given that error rate, pure heuristic classification is
  barred from ever asserting **Feasible now** (reserved for platforms this repo already ships, or
  rows this session individually verified) — unverified rows land in either **Feasible later**
  (the default, matching this repo's own baseline assumption in `research.md` that most boards are
  JS SPAs or HTML needing a scrape/parse adapter) or **Infeasible** (robots/bot-block,
  browser-or-login-required, paid-tier, or CAPTCHA signal found in the card's text).
- Feasibility tiers, as defined for this catalog: **Feasible now** (a no-auth feed/API exists, or
  the board is backed by an ATS this repo already ships); **Feasible later** (publicly reachable
  with no login/key/browser, but needs a dedicated scrape/parse adapter this repo does not have —
  technically possible, not urgent); **Infeasible** (requires auth, login, a registered API key, a
  paid tier, CAPTCHA, browser rendering, or an unresolved ToS/robots conflict — i.e. not currently
  shippable for any reason, structural or policy).
- This repo does not yet enforce `robots.txt` at runtime (ADR-0002 names this as an open gap), so a
  robots-disallow signal here is recorded as a feasibility fact about the source, not a statement
  about this repo's current enforcement.
