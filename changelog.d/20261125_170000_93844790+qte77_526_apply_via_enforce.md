### Security

- `persist-offer` checks the prefill pack in code, not only in the tailor prompt (#526). Every line is normalised first (NFKC, and Unicode format characters such as zero-width spaces are removed). Then the allowed items are removed as whole strings:
  - the job record's url, as stored or in canonical form;
  - the exact host and path of a link in the JD (no query, no fragment);
  - an email address from the JD;
  - the candidate's own links from the local evidence library.
- A line that still holds anything link-like or address-like is replaced by a fixed note: `://`, `//`, `www.`, `@`, `<`, `>`, a markdown link or reference, a backslash, an HTML entity, a non-web scheme, or a `host.tld` followed by `/`, `?`, `#` or `:`. Any label the agent wrote is not trusted, so every line is checked.
- The code writes the route line itself: `**Apply via:** <route>`. The route is the first allowed item on the first line that starts with "apply via", else the record's url, else `[NEEDS HUMAN INPUT]` (fail closed).
- A JD route on another host than the record's url is kept, as the prompt contract allows, but flagged.
- Replacements happen before anything renders, so `prefill-pack.md`, `result.json` and the dashboard get the checked text. An `apply-via-check.md` sidecar explains in fixed text, without repeating what was removed, and says a replacement can be a false positive (a name such as Node.js reads like a link). Counts in `result.json` keep the sidecar on re-render.
- Replacing, not raising: a failed persist leaves the offer "missing" for `pack-plan`, which would re-tailor an injected JD in a loop (ADR-0005). An unreadable `jobs-raw.json`, including one that is not UTF-8, fails closed instead of raising.
- Known limit: re-checking a pack after its record has left `jobs-raw.json` fails closed.
- `canonical_url(url, ats)`:
  - Path-addressed ATSes (Greenhouse, Ashby, Lever, Recruitee, Personio) keep only the query keys they need (Greenhouse: `gh_jid` and `board`) and lose the fragment.
  - Other sources (RSS, manual, unknown) keep their query, minus tracking params, and lose the fragment, so query-addressed items never collapse into one url or RSS id.
  - Ingest and RSS links pass the ATS. Scored rows, which hold no ATS, keep the old tracking-only rule.
- On the current corpus, 178 Greenhouse embedded-board urls lose a bare numeric key and 43 fragments are dropped; no record id changes.
