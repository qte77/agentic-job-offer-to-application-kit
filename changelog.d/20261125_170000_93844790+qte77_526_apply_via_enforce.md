### Security

- `persist-offer` checks every "Apply via" line of the prefill pack in code, not only in the tailor prompt (#526). Each link must be http or https with no userinfo. It must be exactly the job record's url (as stored, or in canonical form) or exactly the host and path of a link in the JD text, with no query and no fragment. An email must be a bare address that appears in the JD. Every other token that looks like a link is checked the same way: a scheme, `//host`, a markdown link target, or a `host.tld/path` route.
- A failing line is replaced by the record's url, or by `[NEEDS HUMAN INPUT]` when the record is unknown or has no http(s) url (fail closed). The replacement happens before anything renders, so the link never reaches `prefill-pack.md`, `result.json` or the dashboard. An `apply-via-check.md` sidecar says so without repeating the rejected text, and a count in `result.json` keeps the sidecar on re-render.
- The line is replaced rather than the persist failing, because a failed persist leaves the offer "missing" for `pack-plan`, which would re-tailor an injected JD in a loop (ADR-0005).
- `canonical_url(url, ats)` keeps only the query keys the record's ATS needs (Greenhouse: `gh_jid` and `board`) and drops every other key and the fragment. Ingest (`record()`) and RSS links pass the ATS. Scored rows, which hold no ATS, keep the old tracking-only normalisation.
- On the current corpus, that changes 178 Greenhouse embedded-board urls (a bare numeric key is dropped) and drops 43 fragments; no record id changes.
