### Security

- `persist-offer` now checks the whole prefill pack in code, not only through the tailor prompt (#526). No label the agent writes is trusted.
  - Every line is first normalised: NFKC, then Unicode format characters are deleted (zero-width characters, tag characters, soft hyphens, the BOM, bidi controls). The normalised line is what gets written, so nothing the check did not see reaches the file or a link.
  - Allowed items are then blanked out as whole strings. Only a space, a tab, the end of the line, or closing punctuation that marked trims may follow one. The allowed items are:
    - the job record's url, as stored or in canonical form;
    - the exact host and path of a link in the JD (no query, no fragment);
    - an email address from the JD;
    - the candidate's own links from the local evidence library.
  - Scheme and host match in any case; the path must match exactly.
  - A line that still holds something that can become a link or carry hidden data is replaced by a fixed note: `://`, `//`, `www.`, an email-shaped `@`, a tag-like `<`, `](`, `][`, `]:`, a backslash, an HTML entity, a web or script scheme, or a control character. On the route line, a bare `host.tld` followed by `/`, `?`, `#` or `:` also counts.
  - Ordinary field text (for example `Node.js/Express`, `GPA 3.85/4.0`, `< 3 months`, `[NEEDS HUMAN INPUT]: start date`) is not touched.
- The code writes the route line itself: `**Apply via:** <route>`.
  - The route is the first allowed item on the first line that starts with "apply via", provided that line passed. Otherwise it is the record's url, or `[NEEDS HUMAN INPUT]` when there is none (fail closed).
  - A later route line is dropped and counted as a replacement.
  - A route that is not the record's url (on another host, or when the record has none) is kept, as the prompt contract allows, but flagged.
- An `apply-via-check.md` sidecar reports replacements in fixed text and never repeats what was removed. Counts in `result.json` keep the sidecar on re-render.
- A failing line is replaced rather than the persist failing: a failed persist leaves the offer "missing" for `pack-plan`, which would re-tailor an injected JD in a loop (ADR-0005).
- An unreadable `jobs-raw.json`, including one that is not UTF-8, fails closed instead of raising.
- Known limits:
  - re-checking a pack after its record has left `jobs-raw.json` fails closed;
  - the candidate's own links (GitHub, LinkedIn, website) are kept only when the local evidence library holds them. It holds none today, so they are removed, and the sidecar says so.
- `canonical_url(url, ats)`:
  - Path-addressed ATSes (Greenhouse, Ashby, Lever, Recruitee, Personio) keep only the query keys they need (Greenhouse: `gh_jid` and `board`) and lose the fragment.
  - RSS, manual and unknown sources keep their query minus tracking params, and lose the fragment.
  - Ingest and RSS pass the ATS. Scored rows keep the old tracking-only rule.
  - On the current corpus, 178 Greenhouse embedded-board urls lose a bare numeric key and 43 fragments are dropped; no record id changes.
